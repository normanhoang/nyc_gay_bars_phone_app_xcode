# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Native **Swift/SwiftUI** iOS app — a tracker for NYC gay bars (browse list/map, log drinks today or backdated, view history/stats/badges). Single-user, fully local (UserDefaults), no network at runtime. Ported from an Expo/React Native app (the `legacy-expo/` archive referenced below is not currently in the tree).

- **iOS 26 only.** Uses SwiftUI's native Liquid Glass (`.glassEffect`). Requires Xcode 26+.
- The `.xcodeproj` is **generated by [xcodegen](https://github.com/yonyz/XcodeGen)** from `project.yml` — do not hand-edit it. After adding/removing/renaming source files, run `xcodegen generate` (sources are globbed from the `NYCGayBars/` dir).

## Commands

```bash
xcodegen generate                                                    # regenerate NYCGayBars.xcodeproj after file changes
xcodebuild -scheme NYCGayBars -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.5' build
xcodebuild -scheme NYCGayBars -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.5' test
# single test:
xcodebuild -scheme NYCGayBars -destination 'platform=iOS Simulator,name=iPhone 17,OS=26.5' test -only-testing:NYCGayBarsTests/GeoTests/testKnownZip
```

Git remotes: `origin` is the old RN repo (`nyc_gay_bars_phone_app`); this repo's remote is **`xcode`** (`nyc_gay_bars_phone_app_xcode`) and `main` tracks `xcode/main` — push there.

Device install (`DEVELOPMENT_TEAM: DZRPJF9JB6` is set in `project.yml`; find the UDID with `xcrun devicectl list devices`):

```bash
xcodebuild -scheme NYCGayBars -destination 'platform=iOS,id=<DEVICE_UDID>' -allowProvisioningUpdates DEVELOPMENT_TEAM=DZRPJF9JB6 CODE_SIGN_STYLE=Automatic build
xcrun devicectl device install app --device <DEVICE_UDID> <built>.app   # retry once; first attempt often fails "connection interrupted"
xcrun devicectl device process launch --device <DEVICE_UDID> com.normanhoang.nycgaybars   # fails if phone is locked
```

App Store IPA (bump `CURRENT_PROJECT_VERSION` in `project.yml` first — ASC rejects duplicate build numbers — then `xcodegen generate`):

```bash
xcodebuild -scheme NYCGayBars -destination 'generic/platform=iOS' -archivePath build/NYCGayBars.xcarchive archive -allowProvisioningUpdates
xcodebuild -exportArchive -archivePath build/NYCGayBars.xcarchive -exportPath build/ipa -exportOptionsPlist build/ExportOptions.plist -allowProvisioningUpdates
# build/ is gitignored — if build/ExportOptions.plist is missing, recreate it:
# a plist dict with method=app-store-connect, teamID=DZRPJF9JB6, signingStyle=automatic, destination=export
```

There is no SwiftUI Preview-based screenshot harness. To screenshot a specific tab on the simulator, add temporary `START_PAGE` scaffolding to `RootTabView` that **renders the target page directly, bypassing the pager** (`if let p = startPage { singlePage(p) } else { ScrollView … }`) — merely seeding the `page`/`scrollPosition` state does **not** scroll it (programmatic `scrollPosition(id:)` writes outside a gesture silently no-op here). Launch with `SIMCTL_CHILD_START_PAGE=N xcrun simctl launch ...`, capture with `xcrun simctl io <udid> screenshot`, then **revert the scaffolding**. The first-launch location alert blocks screenshots and `simctl privacy grant location/location-always` does **not** suppress it (even after `erase` + fresh boot) — `xcrun simctl privacy <udid> revoke location com.normanhoang.nycgaybars` does (app just loses distances/Nearest). Host-level AppleScript clicking on the Simulator window is sandbox-blocked (System Events sees 0 windows). For App Store 6.5" shots, create an **iPhone 13 Pro Max** sim — native 1284×2778, no resize step — and clean the status bar with `xcrun simctl status_bar <udid> override --time "9:41" ...`.

To *interact* with the UI (taps/swipes/scrolls), host-level clicking is unreliable (no idb/axe installed; the Simulator window is often offscreen so cliclick can't reach it). What works: add a **temporary `bundle.ui-testing` target** to `project.yml` + an XCUITest that drives the flow and attaches screenshots (`XCTAttachment(screenshot:)`, `.keepAlways`), run with `-only-testing:`, extract via `xcrun xcresulttool export attachments --path <xcresult> --output-path <dir>` (its manifest.json maps exported names), then **revert project.yml, delete the test dir, rerun xcodegen**. XCUITest selector gotchas: `staticTexts["Stats"]/["History"]` also match the tab-bar labels, and stat-card subtitles shadow neighborhood names (FAVORITE BAR shows "Hell's Kitchen") — assert on unique markers like `"TOTALS"` or the calendar month title instead. Seed state before launch: `xcrun simctl spawn booted defaults write com.normanhoang.nycgaybars "@gaybars/visits" -data <hex of JSON [Visit]>` (same for `@gaybars/visited`, a JSON `[String]`).

SourceKit IDE diagnostics routinely flag cross-file types as "Cannot find X in scope" in this repo — stale-index noise; trust `xcodebuild` output.

## Architecture

Plain SwiftUI + two `ObservableObject` stores injected as environment objects from `NYCGayBarsApp` (`VisitsStore` → `BadgesStore`). No third-party deps.

### Data is generated, not hand-written
`NYCGayBars/Data/Resources/{bars,neighborhoods,zips,meta}.json` are **build artifacts**, decoded once by `AppData` into `AppData.bars/neighborhoodPolygons/zipCentroids/neighborhoods/region`. Use the precomputed `AppData.barsById` / `AppData.barsByNeighborhood` dictionaries for lookups — don't linear-scan `bars`. CLAUDE history references a `legacy-expo/` pipeline (`gay_bars.csv` + `scripts/*.mjs`) as the original source of truth — **that dir is not in the working tree**, so these JSON files are currently edited/regenerated **directly** with throwaway Python scripts.

Neighborhood polygons are built from external NYC neighborhood GeoJSON, not drawn by hand:
- **Outer boroughs (Brooklyn/Queens)** use the **Pediacities** common-name set (`custom-pedia-cities-nyc-Mar2018.geojson`); **Manhattan** polygons are hand-tuned (12th-Ave west edges; the HK/Chelsea divider follows W 37th St's diagonal).
- Each bar's `neighborhood` is assigned by **point-in-polygon**; a few border bars were reassigned by explicit user calls (e.g. BASEMENT NY → Williamsburg even though its pin falls just outside that polygon — `bar.neighborhood` drives filtering/badges, polygon containment only drives map tap).
- **Invariants:** every polygon must be **valid + simple + non-overlapping**, stored as a single ring. The reliable pipeline: `buffer(0)`-clean each input → `unary_union`/`difference` → `simplify(~0.0003, preserve_topology=True)` → `set_precision(1e-6)` (grid-snap) → take the largest exterior ring. Skipping the input clean or running `simplify` last on an invalid ring leaves **zero-width antennas that render as stray lines** inside the boundary. `shapely` is required (`pip install shapely`).
- When the neighborhood **set** changes, also update `meta.json`'s `neighborhoods` list, the affected `bar.neighborhood` values, and `Stats.borough()`'s `brooklynHoods`/`queensHoods` sets (a hardcoded name→borough map; stale names silently count as Manhattan and break the boroughs badge). Zip expectations in `LogicTests` are nearest-*bar* based.

### State + persistence
- `VisitsStore` — `visits`, `visitedBars`, `hydrated`; persists JSON to UserDefaults keys `@gaybars/visits`, `@gaybars/visited`. A `Visit` aggregates drinks per type for one local calendar day; a **zero-drink check-in** is a valid visit (`setVisited`). Backdated visits are stamped **noon local** so the ISO date round-trips the day key; future days are refused. `visitedIds` is a **cached stored `@Published`**, not computed — any new mutation must call `refreshVisitedIds()`. `Visit.dayKey` is derived once at decode/create and **never encoded** (excluded via `CodingKeys`); use it instead of re-parsing `DayKey.key(iso:)`.
- `BadgesStore` — recomputes badges from visits, persists first-earned timestamps (`@gaybars/badgeDates`), and drives the unlock-toast queue. It is **not** self-subscribing: `RootTabView` calls `badges.reconcile(visits:visitedIds:)` on appear and via a **single** `.onChange` keyed on a combined `ReconcileKey(visits, visitedBars)` so one mutation triggers one reconcile.

### `DayKey` (gotcha)
Day keys are `"year-month-day"` with a **0-indexed month** (mirrors JS `getMonth()`), so June 24 2026 is `"2026-5-24"`. `DayKey.toDate` rebuilds noon-local. All streak/badge/calendar logic depends on this round-trip — don't "fix" the month to 1-indexed.

### Logic lives in `Logic/` (pure, unit-tested)
`Stats` (all 30 badges + `MILESTONE_BADGE_IDS` + totals/streaks), `Geo` (distance, proximity ordering, ZIP lookup), `DayKey`, `Drinks`, `ZipQuery`. `NYCGayBarsTests` covers these.

### `Services/`
`LocationManager` wraps CoreLocation (one-shot when-in-use request; feeds `Geo`'s proximity ordering — losing permission just drops distances, per the CLAUDE.md screenshot note above). `Haptics` centralizes `UIImpactFeedbackGenerator`/`UINotificationFeedbackGenerator` calls used from drink logging and badge unlocks.

### Social layer (`Stores/SocialStore` + `Services/CloudKitSocial`)
Optional Friends feature on the **CloudKit public database** (container `iCloud.com.normanhoang.nycgaybars`) — no server, no third parties. `SocialStore` is a `@MainActor` singleton (`SocialStore.shared`) injected as an environment object *and* used by `AppDelegate` push callbacks; `CloudKitSocial` is the stateless async CK wrapper.

- **Record types:** `Profile` (recordName `profile-<userRecordName>` — custom names can't start with `_`), `FriendRequest`, `Friendship`, `CheckIn`. Public-DB writes are **creator-only**, so a friendship is **one record per direction**: B accepting A = B creates `Friendship{B→A}`; A's device sees it (silent push or refresh), verifies an outgoing request existed (mutual-consent guard), then creates the mirror. Nobody ever edits the other party's records.
- **CloudKit query reads are eventually consistent AND non-monotonic** (a later query can return staler results), so derived friend/request state must never hinge on a single fetch. Three invariants guard the accept flow: `accept()` stamps `prefs.ignored` (via `Social.acceptStamp`) so the accepted request stays hidden until the sender's record is actually deleted; `Social.retainedFriendIDs` keeps a cached friend through 300s of query absence (own `Friendship` records are only deleted by one's own device, so absence = replica blip); and `refresh()` is single-flight (`activeRefresh`) so a stale run can't overwrite a fresh one or double-write the handshake mirror. Don't weaken any of these individually — they cover the same window.
- **Check-ins are fanned out per-recipient:** sharing creates one `CheckIn` per send-enabled friend (`recipientID` field). Push subscriptions are per friend with predicate `authorID == F AND recipientID == me` and exist only for un-muted friends; Tonight feed queries `recipientID == me AND ts > now-6h`. This is what makes the per-friend send/get toggles and unfriend-revocation actually enforceable — don't collapse it back to a single broadcast record.
- **Check-in pushes are disabled** via the `Social.checkInPushEnabled` flag (`Logic/Social.swift`, currently `false`) — judged too noisy; friends see check-ins in the Tonight feed instead. When off, `SocialStore.syncSubscriptionsIfNeeded` requests zero check-in subs, so `CloudKitSocial.syncSubscriptions` also **deletes** any existing `sub-checkin-*` on the next refresh (devices stop getting alerts within one sync). Check-in *records* are still written (Tonight feed needs them); friend-request pushes are unaffected. The bell/get toggle is inert while off. Flip the flag to `true` to restore per-friend check-in pushes (subs re-create on next refresh).
- **Prefs** (`SocialPrefs` in `Logic/Social.swift`, unit-tested): sparse `sendOff`/`getOff` sets so new friends default on; device-local under `@gaybars/socialPrefs`. Profile/friends caches: `@gaybars/socialProfile`, `@gaybars/socialFriends`.
- **Push:** CloudKit sends APNs itself (no keys/server). Alert text comes from `alertLocalizationKey` in `en.lproj/Localizable.strings` with args from record fields; tapping a check-in alert deep-links via `barId` in `desiredKeys` → `SocialStore.deepLinkBarId` → `RootTabView` sheet. Own `CheckIn` records >24h old are deleted client-side on `start()`.
- **CloudKit dashboard is manual:** record types auto-create in the dev environment on first write, but queryable indexes (`Profile.code`, `FriendRequest.fromID/toID`, `Friendship.ownerID/friendID`, `CheckIn.authorID/recipientID/ts` + `ts` sortable) must be added by hand, and the schema **deployed to Production before any TestFlight/App Store build**. End-to-end testing needs **two devices with different iCloud accounts**; the simulator (no iCloud) only exercises the "sign in to iCloud" gate.
- **Add-friend links:** URL scheme `nycgaybars://addfriend?code=X` (registered in `project.yml`). The **QR encodes the raw scheme** (`Social.addFriendDeepLink`) so it opens the app offline with no web dependency. The **texted share link** is the https `docs/add-friend.html#<code>` page (`Social.addFriendLink`) — custom schemes aren't tappable in iMessage, so the page bounces into the app and, for people without the app, links to the App Store (`APP_STORE_URL` const in the page). Build/parse helpers in `Logic/Social.swift` (`addFriendDeepLink`/`addFriendLink`/`parseAddFriendURL`, unit-tested); `SocialStore.handleAddFriendLink` auto-sends the request once onboarded.
- **`docs/` pages are user-facing policy** (`privacy.html`, `support.html`, `appstore/index.html`): any privacy-relevant change to the social layer must be reflected there and in `PrivacyInfo.xcprivacy` (currently Name / User ID / Other User Content — linked, no tracking).

### Liquid Glass (`Theme/Glass.swift`) — chrome vs panels
`.glassSurface(radius:bordered:)` (native `.glassEffect`) is for **interactive chrome only** (search bars, toggles, tab bar, buttons, toasts). Static content (stat cards, calendar, visit cards, badge tiles) uses a plain `.contentPanel()` / `Color.white.opacity(0.05)` rounded rect — native glass draws a luminous rim that reads as a border. Never put an `opacity` modifier on a glass element. `AppBackground` (gradient) must sit behind glass so it has colour to refract.

### Navigation shell (`Screens/RootTabView.swift`)
Three pages in a horizontal paging `ScrollView` (`.scrollTargetBehavior(.paging)` + `scrollPosition(id: $page)`) with a custom floating glass tab bar overlaid (content-hugging, fixed-width tabs, centered — not full-bleed). The active tab's magenta `Capsule` lozenge is placed by **`matchedGeometryEffect`** onto each tab's fixed-size content box (identical at every position — do not go back to manual offset math). **`pillPage` is decoupled from `page`:** a tap sets both, moving the pill with a fast `.snappy` (instant feel, no bounce); a swipe settles `page` → `.onChange(of: page)` springs `pillPage` with the bouncy `Anim.tab`. Wrapping the tap pill-move in *some* animation is required — without a transaction the matched-geometry pill is removed+reinserted and flashes. Explore's map mode disables horizontal paging via `TabSwipe` (the map needs to pan); `scrollDisabled` only applies on page 0. `TabSwipe` also broadcasts the current `page`; each page owns a `ScrollPosition` and scrolls itself to top when `tabSwipe.page` changes to another index — the reset happens while offscreen, so returning to a page always lands at the top with no visible jump.

### Map framing (`Screens/BarMapView.swift`)
Selecting a neighborhood programmatically reframes the camera; zooming out far enough (2+ neighborhoods visible, span > 1.2× framed) snaps the filter back to `All`. The framed span must be the **actual rendered** span, captured from the first `onMapCameraChange` after a reframe via the `awaitingFrame` flag — MapKit enlarges a region to fit wide/non-square bars, so using the *requested* `latitudeDelta` made wide neighborhoods (e.g. East Williamsburg) instantly snap back to `All`.

### Motion (`Components/Motion.swift`)
Reusable springs in `Anim` (chip/press/progress/toast/tab) mapped from the original RN reanimated values. `PressableScale` is a `ButtonStyle`; `CountUp`/`ProgressBar`/`Confetti`/`BadgeToast` are the animated primitives.

### Modals
`BarDetailSheet` (drink logging) is shown as a `.sheet` from Explore (logs today) and **in-place** inside `LogDayPicker` for backdated logging — when hosted in-place it takes an `onClose` closure instead of `@Environment(\.dismiss)`.
